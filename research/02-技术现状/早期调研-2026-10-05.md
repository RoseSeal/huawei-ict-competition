# 海事 × AI Agent 调研：行业近况与创新点

> 2026-10-05 时点的调研，此后未更新。正文写作时未读代码仓库，部分结论已由文末附录更正，以附录为准。当时尚未选定赛题（现按赛题 1 准备），文中“海图”即 map-system。

## 调研说明

本次调研梳理海事 AI 与 Agent 技术近况，寻找可基于海图开展的候选创新点。

- **时间窗口**：以 2025 年下半年至 2026 年 10 月为主，更早的工作只作背景。
- **基线**：海图现有能力 = AIS/MQTT 数据管线、CPA/TCPA 碰撞引擎、SSE/WebSocket 推送、GraphRAG 航行建议、GRU 内河轨迹预测。本次未读仓库，复用度按模块概况判断。
- **导师两篇参考**：NavGPT（LLM 驱动的视觉语言导航 VLN）、RiverVLN（无人艇内河 VLN，2026-09）。不做深度分析，只用于定位交叉方向。
- **来源**：arXiv、OpenReview、期刊页、GitHub（topic 页与论文附带仓库）、华为官网与开发者文档、IMO 等官方页面。只收录打开过原页面的来源。

## 结论速览

最值得做的是“可核验 + 主动式”的岸基海事 agent（C1 + C2）：空位明确，海图现有模块能复用大半。

1. **轨迹预测已经很拥挤**。近一年扩散、MoE、推理 LLM 强化学习、场景级数据集轮番出现，里面已有长江口的工作。继续在这里“换模型”很难有新意。
2. **LLM 做避碰判断最常见的失败是算错数、判错规则**。DTU 在 50 个真实场景上的评估结论是未微调模型不可用；把计算交给确定性工具并核验输出，是直接的改进方向。
3. **船载 LLM agent 已不新**：武汉理工航运学院 2026-03 已发表 MARTIAN。岸基、持续运行、主动预警的 agent 在本次检索范围内未见。
4. **内河规则是干净的空白**。现有 LLM 避碰工作全部基于 COLREGs，没有《内河避碰规则》版本，也没有公开的真实场景会遇推理基准。
5. **Agent 工程的重心在 harness**。安全、验证、触发机制是 2026 年的热点；MCP 与 A2A 已归入同一基金会。
6. **华为平台能接住这类作品**。AgentArts 2026 年新增智能体卫士、评估器和 MCP 可观测；Nexent 可本地部署。第十届创新赛特等奖中有武汉理工。
7. **导师的 VLN 方向和海图有自然接口**：岸基 AIS 能给船载视觉补上超视距信息（C4），但工作量大。

## 海事 AI 近况

轨迹预测的主线已经从“换更强的序列模型”转向“语义/环境先验 + 安全筛选 + LLM 推理”。监管侧 2026 年是节点年：MASS Code 生效、S-100 ECDIS 可合法使用、国内发布《智能航运2030行动计划》。

### 轨迹预测与风险

| 时间 | 工作 | 要点 | 对海图的意义 |
|---|---|---|---|
| 2026-09 | [RP-HJD](https://www.frontiersin.org/journals/marine-science/articles/10.3389/fmars.2026.1929840/full)（上海海事大学） | 长江口；物理先验 + 分层扩散生成多候选 + 安全筛选；ADE 68.9 m，安全违规 0.27%，76 ms | 同为长江场景，最直接的对标 |
| 2026-09 | [M³-Former](https://arxiv.org/html/2609.10559)（国科大） | LLM 编码船舶静态属性与航行意图，MoE 融合；4 h 预测 ADE 降 4.4% | GRU 可借“静态属性语义先验” |
| 2026-07 | [NaviAIS / NaviLane](https://arxiv.org/html/2607.18887)（东北大学） | 场景级数据集，矢量化航道先验，覆盖内河/湖泊/海上；码本 + 世界模型反事实风险排序 | 公开内河基准，可用来做外部验证 |

| 2025-08 | [AIS-LLM](https://arxiv.org/html/2508.07668v1) | 时序编码器 + Qwen2-1.5B，统一轨迹预测、异常、碰撞风险、文本解释 | 模块和海图一一对应，“统一模型”路线的代表 |

### 异常检测与可解释

- [等式驱动的合成异常](https://arxiv.org/html/2606.29721v1)（2026-06，首尔大学 + KRISO）：LLM 只负责打分决定异常注入位置，异常本身由运动学方程合成，解决 AIS 没有异常标签的问题。
- [轨迹的语境化自然语言描述](https://arxiv.org/html/2603.12287)（2026-03）：AIS + OSM/气象/水深 → 航次叙述；大模型忠实度高，但距离、时长等**数值计算仍出错**。

### 监管与产业

- **IMO MASS Code**：2026-05 MSC 111 通过，2026-07-01 起非强制生效（经验积累期），强制版最早 2032-01-01；要求人类船长保留干预能力，远程控制中心需认证（[DNV](https://www.dnv.com/news/2026/imo-mcs-111-new-mass-code-adopted/)）。
- **S-100 ECDIS**：2026-01-01 起可合法使用，2029-01-01 起新装 ECDIS 必须符合新标准；S-101/102/104/111/129 首批规范 2025-01 通过（[SAFETY4SEA](https://safety4sea.com/s-100-ecdis-implementation-timeline-key-dates-for-operators-and-ecdis-manufacturers/)）。
- **国内政策**：[《智能航运2030行动计划》](https://www.mot.gov.cn/gongkai/zcjd/202603/t20260331_4202805.html)（2026-03-31）点名“智能航行场景认知与推理、人机协同”、遥控驾驶中心、运行监测系统；[《“人工智能+交通运输”典型应用场景创新行动方案》](https://xxgk.mot.gov.cn/jigou/kjs/202606/t20260624_4208160.html)（2026-06）列出船岸协同、船闸调度、编队航行、多源融合监测预警。两份文件都没有点名大模型或智能体。
- **产业**：生产级产品集中在视觉避碰（Orca AI）、风险与制裁情报（Windward）、航次与港口优化（ZeroNorth、Portcast）；LLM 智能体基本还停留在企业内部工作流自动化（[DSG.AI, 2026-07](https://www.dsg.ai/blog/maritime-ai-companies-2026)）。

## Agent 技术前沿

2026 年的共识是“agent = 模型 + harness”，竞争点从模型能力转向运行时工程：上下文、验证、权限、状态。协议层基本定型。对海事这类安全攸关场景，最有用的是三条线：可验证的工具调用、确定性的运行时约束、以及由轻量模型决定何时唤醒 LLM 的主动式架构。

| 方向 | 代表工作 | 要点 | 可借鉴到海图 |
|---|---|---|---|
| Harness 体系化 | [Agent System and Harness Design 综述](https://arxiv.org/abs/2606.20683)（2026-06） | harness 拆为观察、上下文、控制、动作、状态、验证六项职责；开放问题含安全、harness 泛化、模型与 harness 协同演化 | T/L/O 分层可以对照这六项职责定位 |
| Harness 实证 | [11 个编码 agent 的源码研究](https://arxiv.org/html/2609.00006v1)（2026-09，Wavestone） | 提炼 7 个子系统；没有一家用 LangChain 等通用框架；代码检索全用确定性方法而非向量检索；Skills 采用率（9/11）高于 MCP（8/11） | 自研 harness 不是落后做法；面试可引用 |
| 代码即 harness | [Code as Agent Harness](https://arxiv.org/html/2605.18747v1)（2026-05，UIUC/Meta/Stanford） | 代码作为可执行、可检查、有状态的推理媒介；开放问题含安全攸关部署的人类监督 | LLM 调用 CPA/TCPA 而不是自己算数 |
| 协议 | [A2A 并入 AAIF](https://www.axios.com/2026/08/17/a2a-agentic-ai-foundation-open-ai-standards)（2026-08-17） | A2A 与 MCP 同属 Agentic AI Foundation，成员 250+ | 把海图能力暴露为 MCP server 成本低 |
| 可验证安全 | [Verifiably Safe Tool Use](https://arxiv.org/html/2601.08012v1)（2026-01，CMU） | STPA 危害分析 → 形式化规约 → 在 MCP 工具边界执行禁止/必须/允许/确认四级策略 | 对应 MASS Code “人类可干预”要求 |
| 证据可追溯 | [Tool-Attested Kernel Proofs](https://arxiv.org/html/2607.12650v1)（2026-07） | 工具输出签名，Lean 4 内核只认可能追溯到工具证据的结论；120 道数值题 100% | 形式化太重，但“结论必须追溯到工具输出”可轻量实现 |
| 主动式 agent | [主动 agent 是否需要 LLM 决定何时唤醒](https://arxiv.org/abs/2605.30152)（2026-05） | 220 MiB 的时序图模型做触发器，F1 平均 +16.7，速度快 4–83 倍 | CPA/TCPA + 规则做触发，LLM 只在需要解释或建议时唤醒 |
| 流式发现 | [Discovery Agents](https://arxiv.org/html/2605.27571)（2026-05，IBM） | Kafka + Flink，多 agent 生成假设 → 编译 FlinkSQL → 校验 → 部署；类型化产物契约做可观测与溯源 | 与海图 MQTT 流水线同构 |

## 交叉方向：LLM/Agent/VLN × 海事

LLM 进入航海决策的工作已有十余篇，但多数让 LLM 自己做数值和规则判断，评测普遍薄弱。岸基侧只有“问了才答”的查询类 agent。导师的两篇属于船载视觉语言导航（VLN）一支，与海图的岸基 AIS 路线输入不同。

| 时间 | 工作 | 位置·输入 | 做法 | 结果与局限 |
|---|---|---|---|---|
| 2026-09 | [RiverVLN](https://arxiv.org/html/2609.23423) | 船载·视觉+语言 | 指令拆成有序语义阶段，跟踪当前阶段，预测考虑惯性的短时轨迹；Unity-ROS 内河仿真 260 条航线 | 闭环成功率 0.79，有实艇部署 |
| 2026-08 | [DTU COLREG 能力评估](https://arxiv.org/html/2608.08281) | 评测·结构化 | 50 个丹麦真实 AIS 会遇场景，测 5 个模型的会遇分类、让路判定、动作建议 | 未微调不可用；GPT-4o 偏保守误报；Mistral 7B 建议违规左转；**未公开基准** |
| 2026-05 | [USV-3.0](https://www.sciencedirect.com/science/article/pii/S0029801826008449)（Ocean Eng.） | 船载·视觉 | VLM 看四路相机，置信度低于 90% 请求人工，人工决策存入时空记忆库复用 | 晴天 100% 成功；雾天感知可泛化，但决策失败导致碰撞 |
| 2026-04 | [MARINER](https://pith.science/paper/2604.08615) | 感知评测·视觉 | 16,629 张图、63 类船、5 类事故的 VQA | 多模态大模型细粒度识别与因果推理差 |
| 2026-03 | [MARTIAN](https://www.mdpi.com/2078-2489/17/3/284)（武汉理工航运学院） | 船载·结构化 | Qwen2.5-14B INT4 跑在 Jetson Orin；SFT + RAG + 8 个确定性工具 | 综合 81.16%；RAG 提升知识题却拉低 COLREG 逻辑题 |
| 2026-01 | [MaRAG](https://www.sciencedirect.com/science/article/abs/pii/S0029801825033049)（Ocean Eng.） | 岸基·文本 | 事故报告 → 知识图谱 + 向量双库检索 | 事故问答与因果推理优于 RAG 基线 |
| 2025-05 | [VTS-LLM](https://arxiv.org/html/2505.00989)（A*STAR/NUS） | 岸基·结构化 | VTS 风险船识别做成 Text-to-SQL，发布 VTS-SQL 基准 | 只回答查询，不主动 |
| 2025-02 | [Navigation-GPT](https://arxiv.org/abs/2502.16402) | 船载·结构化 | 大模型 ReAct 调工具 + 微调小模型出建议 | 与 DeepSeek-R1、GPT-4o 对比 |
| 2024-11 | [LLM-COLREGs ASV 控制](https://pith.science/paper/2411.16587) | 船载·数值 | GPT-4 输入 DCPA/TCPA，输出让路/直航，下层 PD 控制 | 仅 4 个场景定性展示；会遇角度区间有重叠 |
| 2023-05 | [NavGPT](https://github.com/GengzeZhou/NavGPT)（AAAI 2024） | 室内 VLN | LLM 显式推理做零样本导航 | 导师参考，思路源头 |

三条观察：

1. **数值与规则判断交给 LLM 是主要失败源**。DTU 评测、轨迹描述论文、早期 ASV 控制论文都暴露同一问题；MARTIAN 的“RAG 拉低逻辑题”也指向“知识检索和规则推理应当拆开”。
2. **船载 LLM agent 本身已不新**，且武汉理工航运学院已发表同类工作；岸基、持续运行、主动预警的 agent 仍是空位。
3. **VLN 与海图的结合点**在超视距信息：船载 VLN 只看得到相机视野，岸基 AIS 能提供视野外的交通态势和预测轨迹。

## 空白点分析

轨迹预测和船载 LLM 决策已经拥挤；空位集中在三处：结论可核验、岸基主动式 agent、内河规则与公开评测。“仍空白”一列的意思是本次检索范围内未见，不等于确认没人做过。

| 问题 | 近期已有工作 | 仍空白 |
|---|---|---|
| LLM 做避碰判断 | Navigation-GPT、MARTIAN、CORALL、DTU 评估、LLM-COLREGs ASV 控制 | 数值与规则结论全部由确定性工具给出，LLM 只组织和解释，并对输出文本做“逐条声明追溯到工具证据”的核验 |
| 评测 | DTU 50 个真实场景（未公开）、MARINER（视觉）、VTS-SQL（查询） | 公开的、基于真实 AIS 的会遇推理基准；内河规则版本完全空白 |
| 岸基 agent | VTS-LLM（问了才答）、MaRAG（事故问答）、[Szczecin 场景级风险 + 运行时保障](https://www.mdpi.com/2077-1312/14/19/1776)（2026-09，无 LLM） | 持续监听 AIS 流、由确定性风险模型触发、主动给出可核验建议的 LLM agent |
| 内河规则 | 所有 LLM 避碰工作都基于 COLREGs；武理已有[三峡-葛洲坝会遇场景参数化建模](https://www.ship-research.com/article/doi/10.19693/j.issn.1673-3185.02973)（2023） | 《内河避碰规则》下的 LLM/agent 推理与评测 |
| 船岸协同 | RiverVLN（只用船载视觉）、USV-3.0（雾天决策失败） | 岸基 AIS 态势作为船载 VLN 的超视距输入 |
| 轨迹预测 | 扩散、MoE、RLVR、码本、语义锚点等，近一年十余篇 | 单纯换模型难出新；更适合作为 agent 的工具 |

|---|---|

### C1 可核验的岸基航行助手

- **做法**：CPA/TCPA、会遇分类、让路/直航判定、轨迹预测都做成 MCP 工具。LLM 写建议时，每个数值和规则结论必须引用一次工具调用的结果；输出前由校验器逐条比对，不一致就拒绝或要求重写。
- **依据**：DTU 评估显示未微调 LLM 的会遇判定不可靠；轨迹叙述论文显示大模型算距离、时长会出错；MARTIAN 发现 RAG 会干扰规则推理；Tool-Attested Kernel Proofs 提供“结论必须追溯到工具证据”的思路，这里只取思路，不上形式化证明。
- **差异**：Navigation-GPT、MARTIAN 也调工具，但不核验最终文本里的声明。本方案把“可追溯”做成硬约束并量化。
- **复用海图**：CPA/TCPA 引擎、GRU 轨迹预测、GraphRAG（只用于检索规则原文）、SSE 推送。
- **评测**：会遇分类与责任判定准确率、数值错误率、无依据声明占比、延迟；对比纯 LLM / LLM + 工具 / LLM + 工具 + 核验三档。
- **风险**：创新幅度中等，差异要靠评测做实。

### C2 事件驱动的主动预警 agent

- **做法**：确定性风险模型（CPA/TCPA + 预测轨迹 + 多船场景聚合）做触发器，风险升级时才唤醒 LLM，生成 VTS 风格的预警与建议；模型调用量、延迟和告警质量一起评估。
- **依据**：VTS-LLM 只回答查询；主动 agent 研究证明轻量模型做触发更准、快 4–83 倍；Szczecin 工作给出了无 LLM 的场景风险 + 迟滞滤波 + 证据质量门控范式，可直接做触发层的参考和基线；IBM Discovery Agents 用 Kafka/Flink 做流式 agent。
- **差异**：在本次检索范围内，海事领域未见“流式 + 主动 + LLM”的岸基 agent。工程难点在背压、去重和告警抑制。
- **复用海图**：MQTT 管线、CPA/TCPA、SSE/WebSocket，几乎全部。
- **评测**：以未来最小会遇距离为标签的告警精确率/召回率、LLM 调用量、端到端 P99 延迟、可支撑的并发船舶数。
- **风险**：标签定义要谨慎；LLM 部分的贡献要靠消融实验证明。

### C3 内河会遇推理基准

- **做法**：从长江 AIS 抽取真实会遇场景，用规则引擎加人工复核标注会遇类型、责任和合理动作；同时覆盖 COLREGs 和《内河避碰规则》；评测通用 LLM、微调模型和工具增强 agent。
- **依据**：DTU 场景未公开；MARINER 是视觉、VTS-SQL 是查询；现有 LLM 避碰工作只用 COLREGs；武理已有三峡-葛洲坝会遇场景建模可借用。
- **差异**：公开、真实数据、内河规则，三点在本次检索范围内都未见。C1 可以作为基准上的方法。
- **风险**：需要懂内河规则的人复核标注，可找航运学院；基准不是“应用”，单独参赛不占优势。

### C4 岸基超视距信息增强的船载 VLN

- **做法**：在 RiverVLN 类仿真中，把岸基 AIS 态势（视野外船舶、预测轨迹、航道约束）通过 MCP 或 A2A 交给船载 VLN agent，评估弯道、桥区、雾天等视野受限场景下的成功率与安全性。
- **依据**：USV-3.0 雾天感知可泛化但决策失败；RiverVLN 只用船载视觉；政策反复提“船岸协同”。
- **差异**：把导师的 VLN 方向和海图的岸基 AIS 接起来。
- **风险**：仿真工作量大；RiverVLN 代码能否跑通待确认；上手 Unity-ROS 有门槛；12 月底前难以完成。

### C5 带不确定性的轨迹工具

把 GRU 从单条预测改为多候选加置信区间，让 agent 能做“最坏情况 CPA”推理。依据是 RP-HJD 的安全筛选和 NaviLane 的多候选排序。偏增量，适合作为 C1/C2 的组件，不单独作为创新点。

### 事实更正

- **GraphRAG 的作用**：规则查询由进程内的 COLREGS 规则图完成；GraphRAG 只检索 12 个合成历史案例，且默认关闭。正文中的“GraphRAG 航行建议”“GraphRAG 检索规则原文”不成立。
- **提交时间**：官方只写“初赛 2026 年 12 月”，具体截止日未公布。
- **MARTIAN**：论文存在（MDPI Information 17(3):284），作者单位“武汉理工航运学院”未能打开原文核实；“武理已发表同类工作”的判断需复核。
- **“快 4–83 倍”**：服务器端 4–7 倍；83 倍是笔记本上对比 Qwen3-8B 的结果；研究场景是个人助理，不是海事。
- **DTU 评估**：摘要只确认 50 个真实 AIS 场景、未微调不可用；“5 个模型”“GPT-4o 偏保守”“Mistral 7B 违规左转”“基准未公开”未在摘要中核实。
- **来源质量**：GitHub 表有 7 行链接到 topic 页而非仓库本身；MARINER 与 LLM-COLREGs 链到第三方聚合站而非 arXiv；《智能航运2030行动计划》链接为交通运输部的解读页。
