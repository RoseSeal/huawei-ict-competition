# 定题判据

> 2026-11-10｜用于本次比赛的方向选择。依据[任务 README](README.md)细化门槛，区分方向可行性、候选贡献与已验证效果。本文确定判据，不对队员交付作验收，也不作最终选题结论。

## 1. 判定原则

- 两个方向分别通过自身门槛，再比较；方向一不成立，不自动转方向二。
- 各项记录为**通过／待补／不通过**：通过须附证据；待补表示证据不足，并列出补充项与截止时间；不通过表示已有证据表明当前范围不满足条件。待补不能视为通过。
- 定题阶段允许效果增益尚待验证，但必须明确解决的问题、改进机制与比较办法。已知结果不支持原主张时，应收窄主张或重新评估方向。
- 两组案例、2—3 条空间转换等数量沿用任务 README，属于前期可行性检查规模，不构成准确率、泛化能力或行业价值的证明。
- A3、A5 结果用于检验判据，不据结果临时改变门槛。确需修订时，记录原因、日期及当时已知结果，并用修订后的判据重新评估两个方向。

## 2. 方向一：航次通告复核

以下三项均须满足。

| 条件 | 最低要求 | 主要依据 |
|---|---|---|
| 材料可用 | 至少两组包含真实通告链、航次输入、空间范围与可核对答案的完整案例，通告与航次的时空条件相互匹配 | A1—A3 |
| 答案可核对 | 按预先固定的规则形成判断和原文依据；核心案例的关键分歧能够通过资料核查或规则澄清解决 | A4 |
| 值得继续投入 | 至少识别一个拟议流程要解决的具体不足，说明简单方法与直接调用强模型分别能做到什么、仍缺什么，并给出改进机制与比较办法 | A5、A6及应用价值证据 |

### 2.1 完整案例与空间资料

- 两组案例应来自至少两条不同的真实通告链。同一条链仅修改出发时间，可形成多个查询，但不计为两组独立材料。
- A3 的 2—3 条空间转换须服务于完整案例，记录来源、坐标系、转换结果与适用范围。仅在地图上画出区域，不代表已能判断航路是否受影响。
- 局部水域须有足以判断航路与水域相对位置的资料；里程重合只能用于候选筛选，不能直接替代空间相交判断。
- 航次可以自行设定，但须明确标注。历史 AIS 与不同年份通告组合时，只作为情景设定，不作为真实航次效果。
- 两组核心案例须能够在明确条件下作出影响判断；其他查询可包含有依据的“信息不足”，不能用全部无法判断的案例替代可行性证明。

### 2.2 A4 标注分歧

沿用[A4 标注规则](A4-标注规则.md)，查询覆盖影响、不影响与信息不足。分歧按原因处理：

| 分歧原因 | 处理 | 对定题的影响 |
|---|---|---|
| 对规则理解不同 | 澄清规则，再用未共同讨论过的查询独立试标 | 可解决则保留；讨论后的同意不能替代独立核对 |
| 材料缺失、输入不确定、引用冲突或原文未覆盖 | 记录具体缺项或歧义，必要时标为“信息不足” | 可作为不确定性处理案例，但不能替代两组可判定的核心案例 |
| 核查后关键判断仍无可靠依据 | 收窄支持范围，或不将该案例计入完整案例门槛 | 若剩余案例不足两组，方向一暂不通过 |

不以降低答案可信度解决标注分歧；少量试标也不用于宣称总体标注一致率。

### 2.3 A5 对照与价值判断

A5 按原任务从 A4 选取 3—5 个案例，先固定答案与输入资料，再比较简单规则或脚本、直接调用强模型的处理情况。保存模型版本、提示词、输入、输出与错误分析；报告全部选定案例，不能只展示失败输出。

- **强模型出错不是必要条件，也不是充分条件。** 若简单方法已能稳定解决，须说明拟议流程还有什么增量；若强模型答对，也须核对人工整理资料、维护通告链或处理更新承担了多少工作。
- 候选不足可以是继承与例外处理、跨通告更新、资料组织或检索。每项须指向具体案例或工作步骤，不能只写“提高准确率”“节省时间”。
- 定题时须有指向具体案例或工作步骤的不足和可执行的比较方案，不要求已证明最终系统优于基线。效果未验证时，材料中写为待验证目标。
- 如简单方法已经覆盖目标任务，且没有其他有证据的困难或可验证差异，则“值得继续投入”一项不通过，应收窄或调整选题。

**理解判断与检索分开评价。** 原 A5 给定完整通告链，主要检验理解与判断；“找不全相关通告”属于另外的检索检查。若增加检索检查，须提前固定来源范围、查询截止时间、人工核对的相关通告集合与比较条件，不能在模型答对后临时改考检索。人工整理参考集合的覆盖限制应注明。

## 3. 方向二：航行 AI 测试与失效诊断

以下三项均须满足。

| 条件 | 最低要求 | 主要依据 |
|---|---|---|
| 失败可信 | 至少一类有明确依据、影响目标任务的失败能够重新运行并捕获；保存输入、版本、预期、实际输出与重跑记录 | B1 |
| 测试可控 | 至少一类条件能够注入，结果有明确判据，运行成本可承受；能区分注入效果与环境干扰 | B2、B3 |
| 值得继续投入 | 明确相对人工脚本、随机扰动与相近工作的具体差异，至少落到失败发现、复现、缩减或诊断中的一个环节，并有可执行的比较方案 | B3、B5及应用价值证据 |

### 3.1 失败、诊断与比较

- 失败定义来自系统契约、独立参考或明确的项目假设，不能只凭模型评价。项目阈值不直接等同于真实航行安全标准。
- 固定已有模型输出的重放，与重新调用模型的重复试验分别记录。前者不能证明模型每次都会产生同一错误。
- AI 给出的原因首先是待验证假设；通过改变相关条件并对照运行后，才能作为该实验环境中的诊断证据。
- 比较方法共用输入资料、约束、判据与运行预算，并记录耗时及模型成本。同一问题重复触发不能计作多个不同失效。
- 具体差异须指向具体失败场景或工作步骤，说明人工脚本、随机扰动在该处的不足，不能只写“自动化”“更智能”。
- AI 引导优于简单方法尚未验证时，明确列为待验证目标；若后续无增益，则收窄贡献或重新评估，不能持续以此作为已成立的创新点。

### 3.2 候选贡献与主张边界

已同步的[B5 材料](B5-相近已有工作.md)将候选差异收窄为：

1. **失效类型**：数据时效、信息到达顺序与 Agent 工具行为共同导致的软件链路失效。
2. **搜索机制**：任务语义与被测系统运行反馈引导的失效搜索。
3. **后处理**：失败用例缩减、假设与对照式诊断、版本回归比较。

以上用于约束候选范围，不要求定题时全部实现。B5 对已调研工作的比较，不等于全面的新颖性证明；本文未重新核验其外部原文。后续应选定有证据且可完成的主张，分别标明已实现、已验证与待验证内容，不能以“平台本身”或“加了 AI”代替贡献。

B4 的第二被测对象可增强通用性证据，但不是本轮定题的必需条件；仅接入本项目时，主张限定于该对象。B6 可提供行业背景与判据线索，不能替代具体用户需求，也不能直接证明平台具有认证能力。

## 4. 共同条件与选择规则

两个方向均须回答：

| 共同条件 | 要求 |
|---|---|
| 应用价值 | 具体用户、现行做法、一个有来源的困难分别是什么。内部自用可以作为证据，但不能直接推成行业需求 |
| 技术差异 | 相对现有工具与简单方法，至少有一个明确且可验证的差异；可以是特定场景下的工程效果，不必宣称方法首创。A6、B5 的检索范围与未核验项须保留 |
| 交付可行性 | 明确最小演示内容、现有基础、关键缺项与补齐办法。关键数据无获取途径、运行底座不清楚或资源不可承受时，不能视为已解决 |

方向通过须同时满足自身三项门槛与上述共同条件。完成逐项判定后按下表选择：

| 结果 | 决策 |
|---|---|
| 只有一个方向通过，另一个不通过 | 选择通过者 |
| 两个方向都通过 | 优先选择应用困难与技术差异证据更强者；证据接近时，选关键依赖更少、交付更可控者 |
| 一个通过，另一个待补 | 通过者作为当前主线；为待补项设定截止时间，不无限等待 |
| 两个方向都未通过，包括仍有待补项 | 收窄范围或补关键证据，不自动转向其中一个 |

若两方向的证据各有优势，记录取舍依据后由 Rose Seal 决定，不为制造唯一答案而临时设置权重。

后续判定记录采用：**条件｜通过／待补／不通过｜证据链接及限制｜补充项与截止时间**。记录实际结果时不改写本文门槛；需要修订的，按第 1 节保留修订依据。
