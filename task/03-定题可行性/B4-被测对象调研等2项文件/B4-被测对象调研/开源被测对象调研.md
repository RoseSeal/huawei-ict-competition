# 开源被测对象调研（第二被测对象候选）

> 任务：在 GitHub、Gitee 查找 1—2 个开源航行 Agent、避碰或船舶辅助决策项目，评估其输入输出、依赖、接口、许可及接入障碍，说明能否接受 B2（map-system，武汉长江段 AIS 避碰系统）的输入、适用哪些判据。
> 调研日期：2026-11-09。仓库信息均取自 GitHub API / raw.githubusercontent.com 原文，非二手转述。

## 结论（TL;DR）

**存在两个可接入的第二被测对象，均为 MIT 许可，接入障碍可控：**

| 候选 | 定位 | 能否接受 B2 输入 | 主要障碍 | 推荐度 |
|---|---|---|---|---|
| **PortGuard-AIS**（TyMill/PortGuard-AIS） | AIS 会遇分析 + 可解释碰撞风险报警 | ✅ 字段几乎一一对应，仅需时间格式适配 | Python ≥3.13；批处理非实时流 | ★★★ 首选 |
| **AIS-RANGE**（jasontimwong/AIS-RANGE） | ECDIS 路径规划 + 实时动态避碰（REST/WS） | ✅ 经 REST/WebSocket 注入 | GDAL + NOAA ENC 海图（无长江水域） | ★★☆ 备选 |

Gitee 未检索到有效候选（见第五节）。

## 一、B2 参考基线（接入评估的对照面）

- **输入**：MQTT 主题 `usv/AisMessage`，JSON 字段 `MSGTIME`（格式化时间串）/ `MMSI` / `LAT` / `LON` / `SOG`（节）/ `COG`（°真北）。
  证据：`simulator/wuhan_yangtze_ais_simulator.py`（`'LAT': round(lat, 6), 'LON': round(lon, 6)`, `'SOG': round(speed, 2), 'COG': round(heading, 1)`）及 `simulator/mqtt_publisher_base.py`（`topic: str = "usv/AisMessage"`）。
- **输出**：SSE `GET /api/v2/risk` 推送 risk_object（targets 内含 `tracking_status`、`position`、`risk_assessment.risk_level / risk_confidence / risk_score`、CPA/TCPA），异常时推送 `ERROR` 事件。
- **重要既有能力**：B2 自带 `simulator/csv_ais_replay_publisher.py`（CSV→MQTT 回放发布器），可将任意 AIS CSV 灌入 B2——同一 CSV 也可直接喂给下列候选对象，天然构成**同源输入的公平对比**。

## 二、候选 1：PortGuard-AIS（首选）

- **仓库**：github.com/TyMill/PortGuard-AIS，Python，v1.0.0，**MIT** 许可（GitHub API license 字段 + README badge 双重确认），有 DOI（Zenodo 10.5281/zenodo.21871438，SoftwareX 论文配套）。
- **定位**（README 原文）："explainable collision-risk assessment, vessel-encounter classification, near-miss mining, and stateful alerts from AIS data. It is intended for restricted port waters, approaches, anchorages, and other traffic-dense areas." 明确声明**不做路径规划、不输出规避机动**，与 B2 的"风险计算+建议"定位同层，可比性最好。
- **输入 schema**（README 原文表格）：必需列 `timestamp`(ISO 8601)、`mmsi`、`lat`、`lon`、`sog`(节)、`cog`(°)；可选 `heading/rot/length_m/beam_m/vessel_type` 等。
- **输出**：assessments / alerts / near_misses 的 CSV+JSON+GeoJSON、HTML 报告；"explicit machine-readable rationale for every assessment"（每条评估带机器可读理由）。
- **接口**：Typer CLI（`validate / assess / near-misses / synthetic / benchmark`）+ Python API（`PortGuardPipeline(PortGuardConfig()).process_csv(...)`，pydantic 模型可直接 `model_dump(mode="json")`）。
- **依赖**：`numpy>=2.1, pandas>=2.2, pydantic>=2.10, rich, typer`，**requires-python = ">=3.13"**（pyproject.toml 原文）。
- **活跃度**：2026-08-10 创建、08-17 最后推送，0 stars、两位作者——新项目、无社区检验，README 质量门（51/51 tests，~93% 覆盖）与可复现基准是其可信度支撑。

**能否接受 B2 的输入：能，适配量最小。** 字段对照：

| B2 MQTT 字段 | PortGuard 必需列 | 适配动作 |
|---|---|---|
| MSGTIME（格式化串） | timestamp（ISO 8601） | 时间格式转换（唯一必改项） |
| MMSI | mmsi | 直通 |
| LAT / LON | lat / lon | 直通 |
| SOG（节） | sog（节） | 直通 |
| COG（°） | cog（°true） | 直通 |

适配方式二选一：① 订阅 `usv/AisMessage` → 缓存为 CSV → 调 CLI/API（约 50—100 行 Python）；② 更简单——**用 B2 自带 `csv_ais_replay_publisher.py` 同一 CSV 双喂**（B2 走 MQTT、PortGuard 走 `process_csv`），零代码侵入。
**适用判据**：其声明的 "kinematic anomaly detection" 与 "validated AIS input model" 使场景 02 类（位置跳变）可直接测；批处理模式下断报行为由数据窗口决定，场景 01 类需按批口径解释；**场景 03（LLM 失败）不适用**（无 LLM 组件）；可把其 alerts 生命周期（hysteresis/persistence/cooldown/dedup）与 B2 的会遇级 advisory 去重（ADR-016）对比。判据沿用两级结构：第 1 级 = 项目自身 README/pyproject 声明与 COLREG Rules 13–17 条款原文；第 2 级 = 通用原则（异常输入需明示、不编造连续性等，与 01-失败场景 场景卡所用判据一致）。

**接入障碍**：① Python ≥3.13（本机模拟器 venv 版本较低，需新建 venv 或 uv 环境）；② 无 MQTT 订阅、无实时流模式（"snapshot and historical processing"），逐秒流式对比需按时间窗分批喂入；③ 面向"受限港域"，与武汉内河场景水域类型不同（不影响接口，影响结论外推）；④ 本船（own vessel）概念与 B2 的三船会遇表述方式有差异，对比指标需统一为"船对会遇"口径。

## 三、候选 2：AIS-RANGE（备选）

- **仓库**：github.com/jasontimwong/AIS-RANGE，Python，v3.3.3，**MIT** 许可（GitHub API license 字段 + LICENSE 文件确认）。
- **定位**（README_EN 原文）："A standards-compliant ECDIS route planning system featuring complete rule validation, TSS compliance checking, real ENC data support, and dynamic collision avoidance capabilities"；自称 "16/16 COLREG/IMO rules"、FastAPI REST 服务 + React UI。
- **接口**：`POST /api/v1/route/plan`、`POST /api/v1/route/validate`、`GET /api/v1/ais/targets`；实时 AIS 走 WebSocket（"WebSocket-based live vessel tracking"）；支持 RTZ 标准航线导入导出。
- **依赖**（requirements.txt）：numpy/scipy/shapely/pyproj + **GDAL>=3.0.0**（读 S-57 ENC）+ fastapi/uvicorn/pydantic；前端 Node 16+。
- **活跃度**：2025-08-22 创建（同日最后推送），0 stars、单作者。

**能否接受 B2 的输入：能，但注入路径较重。** 其 AIS Manager 接受外部目标数据（`GET /api/v1/ais/targets` 提供查询、WebSocket 提供实时流），B2 的 MQTT→JSON 报文经小型桥接服务转成 REST/WS 载荷即可注入；字段（MMSI/lat/lon/sog/cog）同样是直通映射。
**适用判据**：实时动态避碰使其对**场景 01/02 类异常输入的实时行为**可测（与 B2 同为流式响应，时间线对齐最有意义）；其 16 条规则引擎 + evidence tracking 输出可作为"规则符合性"维度的独立判据源；无 LLM 组件，场景 03 不适用。

**接入障碍**：① **GDAL 在 Windows 上安装重**（常见需预编译 wheel 或 conda）；② 海图为 NOAA S-57（美国海域），**无长江/武汉 ENC**，武汉场景只能脱离海图做纯 AIS 会遇测试，其 TSS/路径规划功能在本水域不可评；③ 文档与代码一致性未经第三方验证（0 star 新项目，"production ready" 为作者自述）。

## 四、推荐与接入路线

1. **首选 PortGuard-AIS**：定位同层（AIS→风险/报警）、字段映射近乎零成本、输出机器可读理由，最适合做"同输入、双实现、对比判据"的第二被测对象。接入路线：新建 Python 3.13 venv → 安装 `portguard-ais` → 用 B2 的 CSV 回放数据直接跑 `assess`，再按时间窗与 B2 SSE 逐段对比 risk level / CPA / rationale。
2. **备选 AIS-RANGE**：需要流式实时避碰对比或规则符合性维度时启用；先在 Linux/WSL 或 conda 中装 GDAL 再试 Windows。
3. 共同注意事项：两仓库均为 2025/2026 年新项目、0 stars、单作者/双作者，**"production ready / 100% rules" 等自述指标未经第三方验证，只能作为第 1 级判据（作者声明），不能当已验证事实**。
