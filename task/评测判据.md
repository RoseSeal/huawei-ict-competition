# 评测判据

场景卡中“预期行为”的依据规则、卡片模板与示例。

## 依据来源

每条预期行为须注明依据的级别和出处。

| 级别 | 来源 | 出处写法 |
|---|---|---|
| 1 | 系统自身的明确约定：文档、ADR、事件协议、代码契约 | 文件路径与章节，如 `docs/EVENT_SCHEMA.md` §3 |
| 2 | 通用工程原则：过期数据不作为当前数据；工具失败须显式报告；引用的依据可追溯到工具输出；缺少数据时说明不确定，不编造 | 写明所用原则 |
| 3 | 航运规范的明确条款：COLREGs、《内河避碰规则》、IMO 设备性能标准等 | 规范名称与条款号 |

## 规则

- 找不到依据的，标注“待确认”，不进入评测集，不判定对错。
- 预期行为在运行前写好，不根据运行结果修改。
- 第 1 级与第 3 级矛盾时，记为设计问题，不计为系统失败。

## 场景卡模板

```markdown
## 场景 <编号>：<一句话描述>

- 输入变化：
- 正常对照：
- 预期行为：
- 依据：第 <级别> 级，<出处>
- 复现步骤：
- 实际结果：
- 状态：待验证 / 符合 / 不符合 / 待确认
```

## 示例

```markdown
## 场景 00：目标船停止发送 AIS

- 输入变化：武汉演示运行中，目标船 900001222 在会遇前停止发送 AIS 60 s，其他船正常发送。
- 正常对照：同一演示不做改动，900001222 持续发送。
- 预期行为：系统标示该目标数据已过期或位置不确定，不将 60 s 前的位置当作当前位置计算风险并给出建议。
- 依据：第 2 级，过期数据不作为当前数据。
- 复现步骤：修改模拟器，使 900001222 在启动后第 200 s 至 260 s 不发布消息；按演示文档 §0 运行，对比两次运行的风险卡片与 SSE 事件。
- 实际结果：未运行。
- 状态：待验证
```

示例仅说明格式，不代表系统已存在该问题。
