## 遇到的阻塞与解决

| # | 阻塞 | 根因 | 解决 |
|---|---|---|---|
| 1 | 首次启动后端失败，前端报 8080 连接拒绝，进程变成"连着 MQTT 但不监听端口"的僵尸 | 启动终端继承了环境变量 `SERVER__PORT=47928`（WorkBuddy 内部端口），Spring Boot 松散绑定将其识别为 `server.port`，绑定冲突导致启动失败；JVM 因非守护 MQTT 线程滞留不退出 | 用 `env -u SERVER__PORT ./mvnw.cmd spring-boot:run` 启动；在普通 CMD/PowerShell 终端直接 `mvn spring-boot:run` 无此问题 |
| 2 | Maven 依赖下载极慢，构建卡在中央仓库校验 | 本机 `~/.m2/settings.xml` 缺失，直连 Maven Central | 新建 `C:\Users\<用户>\.m2\settings.xml`，配置阿里云镜像 `https://maven.aliyun.com/repository/public` |
| 3 | 文档命令为 Mac 风格（`simulator/venv/bin/python`） | Windows 虚拟环境路径不同 | 改用 `simulator\venv\Scripts\python` |

## 给其他 Windows 成员的建议

- 后端启动失败但 java 进程不退出时，先到任务管理器结束残留 `java.exe` 再重启，否则会误判为"已启动"。
- 首次运行先确认三件事：Docker Desktop 已就绪、`application-local.properties` 已从 example 复制、`llm.enabled` 与 key 组合合法（key 留空时必须 `llm.enabled=false`，否则启动失败）。
