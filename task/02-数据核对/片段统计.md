# 片段统计（FVessel Clip-10 / clip-01）

> 任务：抽取一个片段，统计同一时间窗口内视频中可见的船舶数与有 AIS 的船舶数。
> 数据来源：官方 HuggingFace 镜像 `https://hf-mirror.com/datasets/gy65896/FVessel` 的 `Clip-10.zip`（2.56 GB，10 个片段，为官方 V2.0 融合标注的子集），本地解压路径 `C:\Users\21979\WorkBuddy\航运\FVessel_data\Clip-10\`。

## 抽取片段

- 片段：`Clip-10/clip-01`（桥区）
- 视频：`2022_06_04_12_05_12_12_07_02_b.mp4`，起止 **2022-06-04 12:05:12 → 12:07:02（北京时间，110 s）**
- 相机：`camera_para.txt` = 经纬度 `(114.327222, 30.600278)`、水平朝向 352°、垂直朝向 -4°、高 20 m、水平 FoV 55°、垂直 FoV 30.94°、内参 fx=2391.26 fy=2446.89 u0=1305.04 v0=855.214
- AIS：`ais/*.csv`，每秒一个文件，字段 `,mmsi,lon,lat,speed,course,heading,type,timestamp`（Unix 毫秒）

## 时间对齐方法

视频绝对时刻 = 文件名起始时刻 + 标注秒偏移（`gt_*.txt` 第一列 `<second>`）。一致性证据：标注覆盖第 2 s–110 s，与文件名时长 110 s 吻合；AIS 时间戳按 UTC+8 换算后与文件名同一日期时刻体系（如 `1654315502004` → 2022-06-04 12:05:02）。

## 发现与提醒

1. **Clip-10 子集内全部可见船都有 AIS**（10 个片段 28 艘可见船全部被官方融合标注匹配到 MMSI），该子集**不能**直接用于评估"覆盖无 AIS 船舶"。
2. 需要"可见 > 有 AIS"的样本时，应取完整 V1.0（40.9 GB，26 个视频）：官方 README 表格显示 video-01（5/4）、video-08（6/5）、video-10（3/1）、video-18（10/6）、video-21（7/6）、video-22（2/1）共 6 个视频可见数大于 AIS 数。本次未下载 V1.0 全量（体积与网络限制，见[本地运行记录](本地运行记录.md)）。
3. 数据格式本身支持无 AIS 船舶：`gt_detection/gt_tracking` 标注全部可见船（不带 MMSI），`gt_fusion` 只含匹配到 MMSI 的船，两者差集即无 AIS 船舶轨迹。
4. AIS 接收范围远大于相机视野：clip-01 全片 12 个 MMSI 在广播，画面内仅 2 艘。**不能**用"距相机距离"判断画面内外（本片段中匹配上的 MMSI 290000000 距相机约 1.7 km，而未匹配的 110000000 仅 176 m——是否在视野内取决于朝向与 FoV 投影，官方提供 `01_demo_transform` 投影代码），融合判断应以 `gt_fusion.txt` 为准。

## 复现

统计脚本为内联 Python（标准库），核心逻辑：

```python
# 可见: gt_tracking 去重 id
# 有AIS: gt_fusion 行 (second, bbox...) 与 gt_tracking 行 (second, bbox...) 相同者 -> 其 id 即"有AIS的可见船"
# AIS: 遍历 ais/*.csv, timestamp 落在 [文件名起始+窗口起点, 文件名起始+窗口终点] 的去重 MMSI
```
